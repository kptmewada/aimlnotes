Unit 1: Introduction to Machine Learning

Machine Learning and Well-Posed Learning Problem

Definition: Machine Learning is the field of study that gives computers the ability to learn from experience (data) without being explicitly programmed (Arthur Samuel). Mitchell (1997): A computer program is said to learn from experience E with respect to some class of tasks T and performance measure P, if its performance at T, as measured by P, improves with E.

ProblemTPE
CheckersPlaying checkers% of games wonGames played against itself
Handwriting recognitionRecognising words in images% words correctDatabase of labelled handwriting
Spam filterClassify email as spam/not% emails correctly classifiedEmails labelled by users

Motivation: (1) tasks too complex to hand-code (speech, vision); (2) huge data volumes; (3) systems must adapt to change and personalise; (4) discovers hidden patterns humans miss; (5) lower cost than manual rule writing.

Applications: fraud detection, image/speech recognition, spam filtering, recommendation systems, medical diagnosis, stock prediction, self-driving cars, machine translation, house price prediction.

Designing a Learning System (checkers example)

  1. Choosing the training experience: direct (board states with correct moves) or indirect (only final outcomes of games, so credit assignment is needed); degree of learner control over the examples; how well training data represents the test distribution.
  2. Choosing the target function: e.g. V: Board → R giving the value of a board state (V = +100 win, -100 loss, 0 draw).
  3. Choosing representation: linear function V(b) = w0 + w1x1 + ... + w6x6, where xi are board features (number of black pieces, red pieces, kings, threatened pieces).
  4. Choosing the learning algorithm: estimate training values Vtrain(b) = V(Successor(b)); adjust weights by the LMS rule: wi ← wi + η(Vtrain(b) - V(b))xi.
  5. Final design: four modules: Experiment Generator, Performance System, Critic, Generalizer.

Perspectives and Issues in ML

ML is viewed as searching a large hypothesis space for the hypothesis that best fits the training data and prior knowledge. Issues: which algorithm for which task; how much training data is enough; how prior knowledge helps; how to reduce overfitting; how to choose the training experience and representation; how to handle noisy or missing data; how to automatically select features; computational cost and scalability.

Concept Learning

Concept learning = inferring a boolean-valued function from training examples of its inputs and outputs (e.g. "EnjoySport"). Hypothesis notation: each attribute is a specific value, "?" (any value) or Φ (no value).

Find-S algorithm:

  1. Initialise h to the most specific hypothesis <Φ, Φ, ..., Φ>.
  2. For each positive example x: for each attribute, if h's value is satisfied by x do nothing, else replace it with the next more general constraint (the value of x first, then "?").
  3. Ignore negative examples. Output h.

Limitations: ignores negatives, cannot tell if it found the only consistent hypothesis, fails with noisy data.

Candidate Elimination: maintains the version space (all hypotheses consistent with the data) through the specific boundary S and general boundary G. Positive example: remove from G inconsistent hypotheses, minimally generalise S. Negative example: remove from S inconsistent hypotheses, minimally specialise G. Inductive bias: the set of assumptions that lets the learner generalise to unseen data (for Candidate Elimination: the target concept is in the hypothesis space).

Bias-Variance and Regularization (exam favourites)

Expected error = Bias2 + Variance + Irreducible error. Bias: error from wrong/simple assumptions (underfitting). Variance: sensitivity to training set (overfitting). Increasing complexity lowers bias, raises variance; the best model balances both. Regularization adds a weight penalty (L2: λ∑w2, L1: λ∑|w|) to the loss, shrinking weights, so the fitted function is smoother and less sensitive to noise: variance falls, bias rises slightly. L2 gives small non-zero weights; L1 gives sparse weights (many exactly zero).

Unit 2: Shrinkage, PCR, Linear Classification

Shrinkage Methods

Why: Ordinary least squares (OLS) has low bias but high variance when predictors are many or correlated. Shrinkage methods constrain/penalise coefficient size, trading a little bias for a large drop in variance, improving prediction accuracy.

Ridge: βridge = argmin { ∑(yi - β0 - ∑βjxij)2 + λ∑βj2 }    Closed form: (XTX + λI)-1XTy
Lasso: same RSS + λ∑|βj|
  • λ (tuning parameter) chosen by cross-validation. λ=0 gives OLS; λ→∞ gives all coefficients → 0.
  • Intercept β0 is not penalised; standardise inputs first.
  • Ridge: shrinks coefficients proportionally, never exactly zero; handles multicollinearity (XTX + λI is always invertible).
  • Lasso: L1 constraint region has corners, so the solution often lies on an axis and some coefficients become exactly zero (feature selection). No closed form.

Principal Components Regression (PCR)

  1. Standardise predictors.
  2. Compute covariance matrix; find eigenvectors (principal directions) and eigenvalues (variance explained).
  3. Keep first M components zm = Xvm which capture most variance (choose M by cross-validation).
  4. Regress y on z1...zM by OLS: θm = <zm, y>/<zm, zm>.

Pros: removes multicollinearity, reduces dimensions, components are orthogonal. Cons: components are built without looking at y, so high-variance directions may not predict y; components are hard to interpret. Ridge vs PCR: ridge shrinks low-variance directions smoothly; PCR discards them completely.

Linear Classification, Separating Hyperplanes

A linear classifier divides the feature space with a hyperplane wTx + b = 0; predict class +1 if wTx + b > 0, else -1. w is normal to the plane; distance of x from the plane = |wTx + b|/||w||. Data is linearly separable if such a plane exists. Perceptron update on error: w ← w + ηyixi. Infinitely many separating planes may exist; the optimal separating hyperplane maximises the margin (basis of SVM). Problems with linear regression for classification: outputs outside [0,1], sensitive to outliers; hence logistic regression.

Logistic Regression

p(x) = P(y=1|x) = 1/(1 + e-(wTx+b))    Log-odds: ln[p/(1-p)] = wTx + b
  • Sigmoid squashes any real value to (0,1), interpreted as a probability; predict 1 if p ≥ 0.5 (threshold adjustable).
  • Decision boundary wTx + b = 0 is linear.
  • Training: maximum likelihood. Loss (cross-entropy) J = -(1/m)∑[y log p + (1-y) log(1-p)], minimised by gradient descent: w ← w - α(1/m)∑(pi - yi)xi. No closed-form solution.
  • Multiclass: one-vs-rest or softmax. Regularisation (L1/L2) can be added.
  • Despite its name it is a classification algorithm.

Unit 3: Naive Bayes, KNN, Trees, SVM, Evaluation

Naive Bayes Classifier

P(C|x1..n) = P(C)∏P(xi|C) / P(x)    Predict: C* = argmaxC P(C)∏P(xi|C)

"Naive" because features are assumed conditionally independent given the class. Steps: (1) compute priors P(C) from class frequencies; (2) compute likelihoods P(xi|C); (3) multiply; (4) choose the class with highest posterior. Use log-probabilities to avoid underflow; use Laplace smoothing (+1) to avoid zero probabilities.

Pros: fast, works with little data, handles many features. Cons: independence assumption rarely true; zero-frequency problem.

K-Nearest Neighbours

Instance-based, lazy learner (no training phase; stores all data). Algorithm: (1) choose K; (2) compute distance from query to every training point; (3) pick K nearest; (4) classification: majority vote, regression: average. Distances: Euclidean √∑(xi-yi)2, Manhattan ∑|xi-yi|, Minkowski.

  • Small K (K=1): low bias, high variance (overfits noise). Large K: high bias, smooth boundary. Choose odd K by cross-validation.
  • Feature scaling (normalisation) is essential. Suffers from the curse of dimensionality; prediction is slow on large data.
  • Distance-weighted voting (weight = 1/d2) improves accuracy.

Decision Trees

A tree where internal nodes test an attribute, branches are outcomes, leaves are class labels. Built top-down greedily (ID3): pick the attribute with the highest information gain, split, recurse until pure or no attributes left.

Entropy(S) = -∑pi log2pi  (0 = pure, 1 = 50/50 binary)
Gain(S,A) = Entropy(S) - ∑(|Sv|/|S|)Entropy(Sv)    Gini = 1 - ∑pi2

Example: 9 Yes, 5 No: Entropy = -(9/14)log2(9/14) - (5/14)log2(5/14) = 0.940. C4.5 uses gain ratio (handles continuous values, missing data); CART uses Gini and gives binary splits. Overfitting control: pre-pruning (max depth, min samples) and post-pruning. Pros: interpretable, no scaling needed. Cons: unstable, overfits, biased to many-valued attributes (ID3).

Support Vector Machines

SVM finds the hyperplane wTx + b = 0 with the maximum margin between classes. Margin planes: wTx + b = ±1; margin width = 2/||w||. Support vectors are the points lying on these planes (closest to the boundary); only they determine the solution.

Kernel trick: for non-linearly-separable data, map x to a higher-dimensional space φ(x) where it becomes separable. The dual form depends only on dot products xi·xj, so replace them with K(xi,xj) = φ(xi)·φ(xj) without computing φ explicitly (cheap). Decision function: f(x) = sign(∑αiyiK(xi,x)+b).

Evaluation Measures for Classification

Accuracy = (TP+TN)/Total; Precision = TP/(TP+FP); Recall = TP/(TP+FN); Specificity = TN/(TN+FP); F1 = 2PR/(P+R); Error rate = 1 - Accuracy. Accuracy misleads on imbalanced data (use F1). Prefer recall when missing a positive is costly (cancer screening); prefer precision when false alarms are costly (spam filter). ROC curve plots TPR vs FPR across thresholds; AUC closer to 1 is better.

Q.2 (1) What is Machine Learning? Differentiate Supervised and Unsupervised Learning

Machine Learning is a branch of Artificial Intelligence in which computer systems learn patterns from data and improve their performance with experience, without being explicitly programmed for each situation (Arthur Samuel). Mitchell's formal definition: a program learns from experience E with respect to task T and performance measure P if its performance at T, measured by P, improves with E. Example: an email spam filter (T = classify email, P = accuracy, E = emails labelled spam/not spam).

Supervised learning: the algorithm is trained on labelled data (input X with known output y) and learns a mapping f: X → y to predict outputs for new inputs. Two types: classification (discrete label, e.g. spam/not spam) and regression (continuous value, e.g. house price).
Unsupervised learning: the data has no labels; the algorithm finds hidden structure, groups or relationships on its own, e.g. clustering customers or reducing dimensions with PCA.

Q.2 (4) Bias, variance and the bias-variance trade-off

Bias: the difference between the average prediction of the model and the true value. It arises from wrong or over-simplified assumptions (e.g. fitting a straight line to curved data). High bias → underfitting: high error on both training and test data.

Variance: how much the model's predictions vary when it is trained on different training sets. A very flexible model changes a lot with small changes in data because it learns noise. High variance → overfitting: very low training error but high test error.

Trade-off (own words): A simple model makes strong assumptions, so it is stable but misses real patterns (high bias, low variance). A complex model fits every detail, so it captures the pattern but also noise and swings with each dataset (low bias, high variance). When we make a model more complex, bias goes down while variance goes up, and the reverse when we simplify, so both cannot be minimised together. The goal is a middle level of complexity where total error is smallest.

Expected test error = Bias2 + Variance + Irreducible error
Model complexityBiasVarianceTrain errorTest errorResult
Too lowHighLowHighHighUnderfitting
OptimalLowLowLowLowestGood generalisation
Too highLowHighVery lowHighOverfitting

How to balance: cross-validation, regularization, more training data, feature selection, ensembling (bagging reduces variance), pruning trees, tuning K in KNN or C in SVM.

Q.2 (5) How regularization reduces overfitting; effect on model weights

Overfitting happens when a model has large, finely tuned weights that fit noise in the training data. Regularization adds a penalty on the size of the weights to the loss function: J(w) = Loss(w) + λ·Penalty(w). The optimiser must now trade off fitting the data against keeping weights small. Smaller weights give a smoother, simpler function that changes less with noise, so variance (and overfitting) falls, while bias rises slightly. λ controls strength (chosen by cross-validation): λ = 0 is no regularization; very large λ pushes weights to zero and causes underfitting.
